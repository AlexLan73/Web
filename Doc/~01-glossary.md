# Глоссарий

Термины курса с указанием урока, где разбираются подробно. Английские названия даны потому, что в документации и сообщениях компилятора встретишь именно их.

Разделы: [латиница](#латиница) · [кириллица](#кириллица) · [часто путают](#часто-путают) · [сокращения](#сокращения)

## Латиница

**`any`** — тип, отключающий проверки. Ошибка не исчезает, а становится невидимой. Не использовать. → 05

**`AbortController` / `AbortSignal`** — механизм отмены асинхронных операций. Передаётся в `fetch`, проверяется вручную в своём коде. Отмена приходит как ошибка `AbortError`, её надо отфильтровать. → 19, 25

**`ArrayBuffer`** — сырая область памяти. Напрямую недоступна, читается через `TypedArray` или `DataView`. → 34

**`as const`** — заявление о полной неизменяемости значения. Отключает расширение типов: массив становится кортежем литералов, поля — `readonly`. Основа приёма «union из данных». → 12

**`asserts x is T`** — функция-утверждение. Если вернулась без исключения, компилятор считает `x` типом `T` на всю оставшуюся область видимости. → 07

**`Atomics`** — атомарные операции над `SharedArrayBuffer`. Позволяют синхронизацию между потоками и настоящую отмену расчёта в воркере. → 36

**`Awaited<T>`** — рекурсивно снимает промисы: `Awaited<Promise<X>>` = `X`. → 10

**backoff** — экспоненциально растущая задержка между попытками переподключения. С джиттером (случайным разбросом), чтобы клиенты не ломились одновременно. → 35

**batching (пакетирование)** — группировка нескольких `setState` в один рендер. С React 18 работает везде, включая промисы и таймеры. → 15

**`bufferedAmount`** — сколько байт ждёт отправки в сокете. Растёт — клиент не успевает, нужно обратное давление. → 35

**`children`** — props, содержащий всё между открывающим и закрывающим тегом компонента. Тип — `ReactNode`. → 18

**`clsx` / `tailwind-merge`** — склейка классов и разрешение конфликтов между утилитами Tailwind. Обёртка обычно называется `cn`. → 31

**`ComponentProps<'button'>`** — все нативные атрибуты элемента как тип. Актуален автоматически, перечислять руками не надо. → 22

**conditional type (условный тип)** — `T extends U ? X : Y`. Вычисление на уровне типов. Аналог частичной специализации шаблонов C++. → 11

**`Controller`** — компонент React Hook Form для управляемых полей, не принимающих `ref` (сторонние селекты, слайдеры). → 30

**`createBrowserRouter`** — конфигурация маршрутов React Router объектом. → 27

**`DataView`** — доступ к `ArrayBuffer` с произвольным смещением и явным порядком байт. Для сетевых протоколов — всегда он, с флагом little-endian. → 33, 34

**`devicePixelRatio`** — отношение физических пикселей к CSS-пикселям. Без учёта canvas получается мыльным на масштабированных экранах. → 31, 34

**discriminated union (размеченное объединение)** — union объектов с общим полем-тегом литерального типа. Центральный приём курса: делает недопустимые состояния невыразимыми. Аналог `std::variant`. → 08

**`dispatch`** — функция отправки действия в редьюсер. Стабильна между рендерами, можно класть в зависимости без `useCallback`. → 25

**distribution (распределение по union)** — условный тип с голым параметром применяется к каждому члену union отдельно. Отключается обёрткой `[T] extends [U]`. → 11

**ESM** — стандартные модули JavaScript, статические. Позволяют tree-shaking. Противопоставляется динамическому CommonJS. → 03

**event loop (цикл событий)** — механизм чередования задач в однопоточном JS. Синхронный код → все микрозадачи → одна макрозадача → снова микрозадачи. → 01

**`Exclude<T, U>` / `Extract<T, U>`** — удаление и выделение членов union. Реализованы через распределение условного типа. → 10

**`FormData`** — чтение значений формы из DOM без состояния. Для неуправляемых форм. → 24

**`forwardRef`** — проброс `ref` внутрь компонента. В React 19 не нужен: `ref` стал обычным props. → 23, 24

**generic (дженерик)** — параметризация типом. Шаблоны C++ без инстанцирования: типы стираются, функция одна. Правило: параметр типа должен встречаться минимум дважды. → 09, 23

**HMR** — замена модуля без перезагрузки страницы с сохранением состояния React. → 26

**`immer`** — библиотека, превращающая «мутации» прокси в создание нового объекта. Для глубоко вложенного состояния. → 29

**`import.meta.env`** — переменные окружения Vite. Только префикс `VITE_` попадает в бандл — и всё, что попало, публично. → 26

**`infer`** — захват части типа внутри условного типа: `T extends (infer E)[] ? E : never`. → 11

**`invalidateQueries`** — пометка кеша Query устаревшим. Основной способ синхронизации после мутации. → 28

**JSX** — синтаксический сахар над вызовами функций. Возвращает объект-описание элемента, не DOM-узел. → 14

**`jsdom`** — эмуляция DOM в Node для тестов. Не умеет: canvas-отрисовку, размеры, воркеры, `ResizeObserver`. → 32

**`keyof`** — union ключей типа. В связке с `T[K]` даёт типобезопасный доступ по ключу. → 06, 09

**`key`** — идентификатор экземпляра компонента в списке. К нему привязано состояние и DOM-узел. Смена `key` = пересоздание компонента. → 16

**`lazy` / `Suspense`** — ленивая загрузка компонента отдельным чанком. Требует default-экспорта. → 26, 27

**`localStorage`** — синхронное хранилище браузера, только строки. Используется через `persist` в Zustand или свой хук. → 21, 29

**mapped type** — преобразование каждого поля объекта: `{ [K in keyof T]: ... }`. На нём построены `Partial`, `Readonly` и переименование ключей через `as`. → 11

**`memo` (`React.memo`)** — пропуск рендера при неизменившихся props (поверхностное сравнение). Работает только вместе с `useMemo`/`useCallback` — иначе бесполезен. Ломает дженерики. → 20, 23

**microtask / macrotask (микро- и макрозадача)** — две очереди event loop. Микрозадачи (промисы, `await`) выгребаются полностью, макрозадачи (таймеры, события) — по одной за виток. → 01

**MSW** — перехват HTTP-запросов на сетевом уровне для тестов. Код приложения не знает, что он в тесте. → 32

**`never`** — пустое множество, тип без значений. Маркер недостижимости; на нём строится проверка исчерпанности `switch`. → 05, 07

**`noUncheckedIndexedAccess`** — опция tsconfig: `arr[i]` получает тип `T | undefined`. Раздражает, ловит реальные баги. → 12

**`Object.is`** — сравнение, которым React и Zustand определяют изменение. Для объектов — по ссылке; отсюда требование иммутабельности. → 15

**`OffscreenCanvas`** — canvas, управляемый из воркера. Отрисовка полностью минует главный поток. → 34

**`Omit<T, K>` / `Pick<T, K>`** — исключение и выбор полей. `Pick` проверяет ключи, `Omit` — **нет**: опечатка проходит молча. → 10

**optimistic update (оптимистичное обновление)** — показать результат мутации до ответа сервера, откатить при ошибке. `onMutate` → `onError` → `onSettled`. → 28

**`Partial<T>` / `Required<T>` / `Readonly<T>`** — модификаторы полей. Все три поверхностные: вложенные объекты не затрагиваются. → 10

**`persist`** — middleware Zustand для сохранения состояния. Обязателен `partialize`, иначе в хранилище попадут функции. → 29

**polymorphic component (полиморфный компонент)** — компонент с props `as`, меняющий тип остальных props в зависимости от тега. Оправдан в дизайн-системе, избыточен в прикладном коде. → 22

**`postMessage`** — обмен с воркером. Второй аргумент — список transferable-объектов, передаваемых без копирования. → 26

**`Promise.all` / `allSettled` / `race` / `any`** — комбинаторы ожидания. Ничего не запускают: промисы уже работают к моменту вызова. → 01

**props** — входные данные компонента. Иммутабельны: данные вниз, события вверх. → 14, 17

**`queryKey`** — идентификатор запроса в кеше Query. Всё, от чего зависит запрос, должно быть в ключе. → 28

**`ReactNode`** — всё, что React умеет отрисовать: элементы, строки, числа, массивы, `null`, `false`. Тип по умолчанию для `children`. → 22

**reconciliation (реконсиляция)** — сравнение старого и нового дерева описаний и вычисление минимальных изменений DOM. O(n) за счёт двух эвристик: разный тип → пересоздание, позиция → тождество. → 15

**`Record<K, V>`** — словарь. С union в качестве `K` требует все ключи — таблица, синхронизированная с типом. → 10

**`refetchOnWindowFocus`** — перезагрузка данных при возврате на вкладку. По умолчанию включено. → 28

**render prop** — props-функция, определяющая отрисовку. До хуков — основной способ переиспользования логики, сейчас — только для отрисовки чужих данных. → 18

**`requestAnimationFrame` (`rAF`)** — вызов перед следующим кадром, синхронизирован с частотой экрана, останавливается в фоновой вкладке. Основа отрисовки в реальном времени. → 20, 34

**`ResizeObserver`** — отслеживание изменения размеров элемента. Для синхронизации буфера canvas с CSS-размером. → 34

**`satisfies`** — проверка соответствия типу **без** изменения выведенного типа. Аннотация делает наоборот: навязывает тип и теряет детали. → 12

**`SharedArrayBuffer`** — общая память между потоками без копирования. Требует заголовков COOP/COEP. → 36

**stale closure (устаревшее замыкание)** — коллбэк, захвативший значение из старого рендера. Самый частый баг в React. Лечится функциональной формой `setState`, честными зависимостями или ref. → 02, 20

**`staleTime`** — время, в течение которого данные Query считаются свежими. По умолчанию 0 — агрессивно, ставь осознанно. → 28

**`StrictMode`** — двойной вызов компонентов и эффектов в разработке. Нужен, чтобы неправильная очистка вылезла сразу. Не отключать. → 14, 19

**structural typing (структурная типизация)** — совпадение типов по форме, а не по имени. Главное отличие TS от C++/Java. Номинативность эмулируется брендом. → 05

**`Suspense`** — граница ожидания для ленивых компонентов. → 26

**template literal type** — строки на уровне типов: `` `on${Capitalize<E>}` ``. Разбор строк через `infer`. На них построена типизация роутеров. → 11

**`toSorted` / `toReversed`** — неразрушающие версии `sort` и `reverse`. Возвращают новый массив. → 04

**transferable object** — объект, передаваемый между потоками по владению, без копирования. После передачи в исходном контексте пустеет. → 26

**tree-shaking** — вырезание неиспользуемого кода при сборке. Работает только с ESM. → 03

**`TypedArray`** (`Float32Array`, `Int16Array`, ...) — типизированное окно в `ArrayBuffer`. `slice` копирует, `subarray` — нет. → 34

**`unknown`** — типобезопасный верх. Хранит что угодно, использовать нельзя до сужения. Правильный тип для внешних данных и `catch`. → 05

**`useCallback`** — стабильная ссылка на функцию. Смысл только один: попадание в зависимости эффекта или в props мемоизированного компонента. → 20

**`useEffect`** — синхронизация с внешним миром: подписки, таймеры, императивные API. **Не** «сделать что-то после рендера». Большинство эффектов в реальном коде лишние. → 19

**`useImperativeHandle`** — императивные «методы» компонента для родителя. Редко: фокус, прокрутка, экспорт canvas. → 24

**`useLayoutEffect`** — синхронный эффект до отрисовки кадра. Для измерений, чтобы не было мигания. → 19

**`useMemo`** — кеш вычисления. Оправдан при реальной дороговизне (>1 мс) или для стабильной ссылки. Не гарантия — React вправе выбросить кеш. → 20

**`useReducer`** — состояние через чистую функцию `(state, action) => state`. Брать, когда поля меняются вместе, есть недопустимые комбинации или логику надо тестировать. → 25

**`useRef`** — ячейка вне цикла рендера: не вызывает рендер, обновляется немедленно. DOM-узлы, таймеры, сокеты, высокочастотные данные. Во время рендера не трогать. → 20

**`useShallow`** — поверхностное сравнение результата селектора Zustand. Нужен, когда селектор возвращает объект. → 29

**`useState`** — состояние компонента. Реализовано массивом и курсором — отсюда правила хуков. Значение — снимок внутри одного рендера. → 02, 15

**`useVirtualizer`** — виртуализация списка: в DOM только видимые строки. От тысяч элементов. → 36

**Vite** — сборщик. В разработке отдаёт модули нативным ESM без бандла, в проде собирает через Rollup. **Типы не проверяет** — нужен отдельный `tsc --noEmit`. → 26

**Web Worker** — настоящий отдельный поток ОС. Общей памяти нет (кроме `SharedArrayBuffer`), обмен через сообщения. Единственный способ считать тяжёлое, не вешая интерфейс. → 01, 26

**widening (расширение типа)** — автоматическое обобщение литерального типа: `let x = 'a'` даёт `string`. Отключается через `as const`. → 05, 12

**Zod** — схемы валидации, из которых выводятся типы. Схема первична — разъехаться с типом невозможно. → 30

**Zustand** — стор с подпиской на срез. В отличие от Context, перерисовывает только тех, у кого изменился выбранный кусок. → 29

## Кириллица

**Всплытие события** — распространение события от элемента вверх по дереву. При этом `target` остаётся исходным элементом, `currentTarget` — тем, на котором обработчик. → 24

**Граница системы** — место, где данные входят извне: сеть, URL, форма, файл, сообщение воркера. Только здесь нужна рантайм-валидация; внутри работают типы. → 07, 30, 33

**Дебаунс** — вызов не раньше, чем через N мс после последнего обращения. Отличать от троттлинга: не чаще раза в N мс. → 02, 19

**Дискриминант** — поле-тег в размеченном объединении. Литеральный тип, одинаковое имя во всех вариантах, разные значения. Строка предпочтительнее числа. → 08

**Замыкание** — функция вместе с окружением, в котором создана. Захватывается переменная, а не значение. Аналог `[&]`-захвата C++, который никогда не протухает. → 02

**Иммутабельность** — изменение через создание нового объекта, а не мутацию. Не идеология, а следствие сравнения по ссылке в React. → 04, 15

**Кольцевой буфер** — массив фиксированного размера с вытеснением старого. Для потоковых данных, когда нужна короткая история. → 35

**Контролируемый / неконтролируемый компонент** — значение приходит снаружи или хранится внутри. По умолчанию неконтролируемый, поднимай при необходимости. → 17

**Обратное давление** — что делать, когда данные приходят быстрее, чем обрабатываются: отбрасывать, буферизовать или просить источник замедлиться. → 35

**Однонаправленный поток** — данные вниз через props, события вверх через коллбэки. Обратной связи нет. → 17

**Подъём состояния** — перенос состояния в ближайшего общего предка компонентов, которым оно нужно. → 17

**Прореживание min/max** — при плотности больше точки на пиксель для каждого пикселя берётся минимум и максимум и рисуется вертикальный отрезок. Пики не теряются, сложность падает до O(ширины). → 34

**Прототип** — объект, к которому идёт поиск свойства, если своего нет. `class` — сахар над этим механизмом. → 03

**Слот** — props, принимающий готовую разметку (`header`, `footer`, `children`). Альтернатива раздуванию props флагами. Props — для поведения, слоты — для содержимого. → 18

**Сужение типа (narrowing)** — уточнение типа компилятором по ходу кода: `typeof`, `in`, `instanceof`, проверка дискриминанта, свой предикат `x is T`. Теряется в замыканиях — копируй в `const`. → 07

**Утечка очистки** — эффект без корректного `cleanup`: висящее соединение, два таймера, два цикла отрисовки. StrictMode показывает сразу. → 19

**Хук** — функция на `use*`, вызывающая другие хуки. Переиспользуется логика, не состояние: каждый вызов создаёт своё. → 21

**Цветовая карта** — соответствие значения цвету в водопаде. Брать перцептивно равномерные (viridis, magma), не радугу — она создаёт ложные границы. → 34

**Чистота компонента** — одинаковые props дают одинаковый результат, во время рендера никаких побочных эффектов. React вправе вызвать компонент лишний раз, дважды или в фоне. → 14

## Часто путают

| | |
|---|---|
| **`slice` vs `subarray`** | первый копирует, второй возвращает представление на ту же память |
| **`target` vs `currentTarget`** | где событие возникло (тип неизвестен) vs где висит обработчик (типизирован) |
| **`Omit` vs `Exclude`** | убирает поля объекта vs убирает члены union |
| **`?` vs `\| undefined`** | поле можно не указывать vs поле обязано присутствовать, но может быть `undefined` |
| **`??` vs `\|\|`** | только `null`/`undefined` vs любое ложное значение (`0`, `''` тоже!) |
| **`type` vs `interface`** | `type` по умолчанию; `interface` — когда нужно слияние объявлений |
| **`unknown` vs `any`** | безопасный верх, требует сужения vs выключенный компилятор |
| **`z.input` vs `z.infer`** | до приведения vs после (различаются при `coerce`) |
| **`status` vs `fetchStatus`** | есть ли данные vs идёт ли запрос — независимы |
| **`isPending` vs `isFetching`** | данных нет вообще vs запрос идёт, в том числе фоновый |
| **дебаунс vs троттлинг** | не раньше чем через N мс после последнего vs не чаще раза в N мс |
| **микро- vs макрозадача** | выгребаются все vs берётся одна за виток |
| **`useEffect` vs `useLayoutEffect`** | после отрисовки кадра vs до неё, синхронно |
| **`memo` vs `useMemo`** | обёртка компонента vs кеш значения |
| **`width` атрибут vs CSS** | размер буфера canvas vs размер отображения — независимы |
| **копия vs представление** | своя память vs окно в чужую |
