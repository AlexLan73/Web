# Часть 1. Теория

## 3.1 Модульная система

В JS две несовместимые системы модулей. Знать нужно обе — вторую хотя бы для чтения.

**ESM** — современный стандарт, статический:
```js
// math.js
export const add = (a, b) => a + b;
export default class Vector { }

// main.js
import Vector, { add } from './math.js';
import * as math from './math.js';
```

**CommonJS** — старый формат Node, динамический:
```js
const { add } = require('./math');
module.exports = { add };
```

Разница принципиальная, не косметическая:

| | ESM | CommonJS |
|---|---|---|
| Разбор | статический, до выполнения | динамический, в рантайме |
| `import` внутри `if` | нельзя | можно |
| Загрузка | асинхронная | синхронная |
| Tree-shaking | работает | нет |

**Tree-shaking** — вырезание неиспользуемого кода при сборке. Работает только с ESM, потому что связи известны до выполнения. Это причина, по которой библиотеки поставляют ESM-сборки: иначе в бандл попадёт вся библиотека целиком.

Как включить ESM в Node: расширение `.mjs` либо `"type": "module"` в `package.json`. В Vite ESM по умолчанию, думать не надо.

**Динамический импорт** — единственный способ загрузить модуль по условию:
```js
if (needCharts) {
  const { Chart } = await import('./chart.js');
}
```
Возвращает промис. В React на этом построен code splitting: тяжёлые страницы грузятся только когда пользователь на них зашёл.

**Именованные vs default:** предпочитай именованные. Default-экспорт можно переименовать при импорте как угодно, что ломает поиск по кодовой базе и автоимпорт в IDE.

## 3.2 `this`

Главный источник путаницы в JS. Ключевой тезис:

**`this` определяется не тем, где функция объявлена, а тем, как она вызвана.**

Это динамическая привязка. В C++ `this` — неявный первый аргумент, известный статически. В JS — тоже неявный аргумент, но подставляется в момент вызова.

Четыре правила, в порядке приоритета:

```js
function f() { console.log(this); }

f();                    // undefined в strict mode (модули всегда strict)
obj.f();                // obj — вызов как метода
new F();                // новый объект
f.call(x); f.apply(x);  // явно заданный
f.bind(x)();            // жёстко привязанный
```

**Потеря контекста** — классический баг:
```js
const counter = {
  count: 0,
  inc() { this.count++; }
};

const fn = counter.inc;
fn();                   // ошибка: this === undefined
```
Метод не «принадлежит» объекту. Это просто функция, лежащая в поле. Оторвал от объекта — потерял привязку.

То же самое при передаче в коллбэк:
```js
setTimeout(counter.inc, 100);          // сломано
setTimeout(() => counter.inc(), 100);  // работает
setTimeout(counter.inc.bind(counter), 100);  // тоже
```

## 3.3 Стрелочные функции

Стрелочная функция **не имеет собственного `this`**. Она берёт его лексически — из окружения, где была создана. Как обычную переменную из замыкания.

```js
const obj = {
  name: 'test',
  regular() { console.log(this.name); },     // 'test'
  arrow: () => console.log(this.name),       // undefined — this из модуля
};
```

Отсюда правило:

- **Метод объекта** — обычная функция (нужен свой `this`)
- **Коллбэк внутри метода** — стрелочная (нужен `this` внешней)

```js
const timer = {
  seconds: 0,
  start() {
    setInterval(() => this.seconds++, 1000);   // стрелка сохраняет this
  }
};
```

Стрелочные функции также не имеют `arguments`, не могут быть вызваны через `new` и не имеют `prototype`.

**Хорошая новость:** в React с хуками `this` не встречается вообще. Функциональные компоненты — чистые функции. Всё выше нужно для чтения чужого кода, работы с классовым легаси и понимания библиотек.

## 3.4 Прототипы

В JS нет классов на уровне рантайма. Есть **прототипное наследование**: у каждого объекта есть скрытая ссылка на другой объект — прототип.

Поиск свойства: нет в объекте → смотрим в прототипе → в прототипе прототипа → ... → `null`. Это цепочка прототипов.

```js
const animal = { speak() { return `${this.name} издаёт звук`; } };

const dog = Object.create(animal);
dog.name = 'Рекс';
console.log(dog.speak());        // работает, метод найден в прототипе
console.log(dog.hasOwnProperty('speak'));   // false — не своё
```

`class` — синтаксический сахар над этим механизмом:
```js
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} издаёт звук`; }
}
// speak лежит в Animal.prototype, не в каждом экземпляре
```

Практически важное отличие от C++: **прототип можно менять в рантайме**, и изменение мгновенно отразится на всех существующих объектах. Отсюда «monkey patching» — правка чужих библиотек на лету. Мощно и опасно; в продакшене не делай.

Ещё следствие: методы хранятся в одном экземпляре на весь класс, а не копируются в каждый объект. Память экономится, но поиск свойства — это проход по цепочке, а не смещение в структуре.

# Часть 2. Проработка

## Задача. Почему `this` теряется в коллбэках

```js
class Poller {
  constructor(url) {
    this.url = url;
    this.count = 0;
  }

  // Вариант 1 — сломан
  startBroken() {
    setInterval(function () {
      this.count++;                      // this === undefined
      console.log(this.url);
    }, 1000);
  }

  // Вариант 2 — стрелка
  startArrow() {
    setInterval(() => {
      this.count++;                      // this из startArrow → экземпляр
    }, 1000);
  }

  // Вариант 3 — bind
  startBind() {
    setInterval(function () {
      this.count++;
    }.bind(this), 1000);
  }

  // Вариант 4 — поле класса со стрелкой
  tick = () => {
    this.count++;                        // привязано навсегда при создании
  };
  startField() {
    setInterval(this.tick, 1000);        // можно передавать без bind
  }
}
```

Разбор:

- **Вариант 1.** `setInterval` вызывает функцию без объекта-хозяина. Правило «вызов как метода» не сработало → `this` пустой
- **Вариант 2.** Стрелка не имеет своего `this`, берёт из `startArrow`, где он корректный. Идиоматичный способ
- **Вариант 3.** Рабочий, но многословный. Встретишь в коде до 2015 года
- **Вариант 4.** Поле класса со стрелкой создаётся **на каждый экземпляр** при конструировании, захватывая `this`. Метод можно отрывать и передавать куда угодно. Цена — своя копия функции в каждом объекте
